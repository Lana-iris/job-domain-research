# 首次使用流程（onboarding）

当项目下缺少 `profile.md` 或 `research-state.md` 时执行。

## 步骤
1. 检测两份知识文件是否存在；缺失则进入收集。
2. 结构化收集（每项给默认值供确认）：
   - **个人信息 → `profile.md`**
     - 目标方向：1 个主方向 + N 个候选方向（**主方向可暂缺**）
     - 个人背景：经历 / 技能 / 行业 / 地域 / 教育 / 能力现状（**只收影响判断的信息**）
     - 目标：转岗 / 晋升 / 求职 / 探索
     - 限制：时间 / 地点 / 薪酬 / 学习投入（**不确定 / 暂缺可留空**）
   - **研究问题 / 信号域 → `research-state.md`**
     - 研究问题：主问题 + 开放问题
     - 信号域：检索位矩阵 + 信号优先类别（**由 LLM 依据输入给初始推荐**，随日报校准）
       - 检索位矩阵：ID、检索主题、必含词/扩展词、每轮最低 query 数、城市范围、平台范围、启用
   - **数据层路径 → `research-state.md` §七**
     - 覆盖台账路径（默认项目目录下 `platform-coverage.xlsx`）
     - JD 库路径（默认项目目录下 `JD扫描-活跃库.xlsx`）
   - **节奏与触发时机 → `research-state.md`**
     - 默认：O1 每日 08:00；O3 每周周五；O4 每月 1 号
3. **目标岗位未明确时**：先协助**拆分候选方向**（依据背景 / 目标 / 限制列出可比较的方向），**不强行要求先选定唯一方向**；主方向可在后续运行中逐步收敛。
4. 生成**信号域初始推荐**并请使用者确认。
5. 使用者确认后，用 `templates/profile.template.md` 与 `templates/research-state.template.md` 落盘两份文件。

## 纪律
- 只收集影响判断的信息，不过度采集。
- 一切默认值需经使用者确认，不擅自决定。
- 不强行要求使用者先选定唯一方向；**不确定 / 暂缺的输入可留空**。
