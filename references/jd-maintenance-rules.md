# 岗位数据维护规则

## 一、目的与边界
- 只负责入库、去重、评分、合并、失效、日志、重新发布、刷新。
- 不搜索、不写覆盖台账、不产出日报。
- 字段定义与写入口径以 `python3 jd_tool.py describe` 输出为准。

## 二、去重与匹配
- 去重键：公司 + 职位 + 城市。同时使用严格键与归一化键（公司名剥离尾部标注、城市取主体；归一化只用于查重，不改写原始值）。
- 活跃库命中任一键 → 拒绝新增；默认合并来源到 `全部来源`，不新增行。
- 失效库命中 → 默认拒绝；只有 `--allow-repost` + `--repost-evidence` 同时具备才放行。
- 校招/社招等批次/层级差异写入 `职位名称`，暂不新增独立字段。

## 三、权重公式（默认，可覆盖）
综合优先级分 = 100 × (0.30R + 0.28C + 0.22F + 0.10Ci + 0.10A)

| 维度 | 符号 | 权重 | 取值 |
|---|---|---|---|
| 时效 | R | 0.30 | ≤7 天=1.0；8–30 天=0.75；31–90 天=0.5；>90 天=0.3；**未知=0.4** |
| 公司 | C | 0.28 | C = 0.6×行业分 + 0.4×梯队分（见 §八） |
| 契合 | F | 0.22 | 契合度(1–5) / 5 |
| 城市 | Ci | 0.10 | 深/广/杭=1.0；北/上/港=0.9；远程=0.9；其他=0.5 |
| 可达性 | A | 0.10 | 当前可达性(1–5) / 5 |

- **发布日期未知 → R=0.4**（不再按 1.0）；存量按需 `recompute`。
- 综合优先级分仅用于**内部**高信号露出与排序，**不作为对外精确排名**。
- 分析时**分别观察三视角**（定性、不参与打分）：Market Signal / Immediate Opportunity（≈当前可达性）/ Portfolio Benchmark；库排序仍按综合优先级分。
- 城市/行业/梯队取值属默认，可按岗位域覆盖。
- **覆盖方式**：权重 / 城市 / 失效阈值 / Sheet 名等默认，可通过 `jd_tool.py --config <config.json>` 覆盖；岗位域层面的覆盖项也可写在 `research-state.md`。

## 四、入库与每日精选
- 所有通过相关性与证据核验的岗位都可进累积库。
- 每日「高信号」精选 **≤10**，仅是日报精选上限，不限制 `add` 入库数。
- `--strict` 是分析三列闸门：`Market Signal`、`Portfolio Relevance`、`Portfolio Benchmark` 必须非空；它不是入库上限。
- 覆盖不足时不凑数、不把「没有找到」写成「没有机会」。

## 五、失效清理
- `purge`：`最后发现日期` 距今 >14 天未再发现 → 移入「JD历史·已失效」。
- `purge` 不是自动调度；必须运行命令并显式 `--apply`。
- 截止日期已过、来源显示已关闭/招满：由扫描时人工确认或 `audit` 提示，不自动清理。

## 六、文件策略、多平台合并、迭代日志
- 单本累积；按去重 ID 更新；同岗多平台合并一行，保留最优来源并写入 `全部来源`。
- 来源字段口径按 `jd-scan-rules.md` 的候选核验要求；字段定义以 `jd_tool.py describe` 为准。
- 来源字段：`来源平台` = 最优单一来源；`全部来源` = `平台|URL；平台|URL`，最优来源在前；为空时用 `来源平台|原文链接` 初始化。
- 向 O1 提供新增 / 合并 / 去重 / 核验淘汰计数，用于 0 新增三态归因。
- 日报中发现的招聘信号同步录入 JD 库时，备注标记【来自日报】。
- 迭代日志 4 列：`日期 | 变更项 | 统计 | 原因`。
- 一次 O2b 运行写一行，由 `jd_tool.py log` 在运行结束时写入。
- `变更项`：新增/刷新/失效摘要，ID 连续时用范围。
- `统计`：运行前后 `活跃a→b，失效c→d`，由工具计算。
- `原因`：一句话说明触发原因。
- 日志缺表或表头不全时自动创建；创建失败则中止保存。
- `audit` 检查日志表头、日期格式、字段非空、最后一行统计与当前工作簿一致。

## 七、可达性
- 可达性 ≠ 契合度：可达性反映「以当前资历能否投进」，随产出物推进应逐月上升。

## 八、公司梯队分（默认示例）
- 行业分：互联网/科技/AI/智造/金融科技=1.0；咨询/教育/医疗科技=0.8；传统=0.5。
- 梯队分：大厂=1.0；外企=0.9；中厂=0.8；创业小厂=0.6；未知=0.7。
- 大厂名单（梯队分=1.0 候选，默认示例，按岗位域维护）：
  - 官网可访问：美团 / 腾讯 / 字节跳动 / 阿里巴巴·淘天 / 蚂蚁集团 / 华为 / 百度 / 拼多多 / 京东 / 大疆
  - 未知待验证：快手 / 小米 / 网易 / 小红书 / 科大讯飞 / 滴滴 / 哔哩哔哩

## 九、重新发布
- 三键命中失效表且来源显示在招 → 可用 `--allow-repost` 重新入册，备注标原 ID。
- 必须同时提供 `--repost-evidence`：原 JD ID、公司、职位、城市、证据链接、核实日期、状态。
- 只给开关不给证据 → 报错。
- 同公司同职能但不同批次/层级 → 视为不同岗。
- 同公司同岗同城多平台 → 合并。

## 十、刷新
- 刷新前必须再次核实详情页仍在招/可投，不能只因搜索引擎结果还在就更新日期。
- 首选 `refresh --evidence <json>`；仅 `在招` / `可投` 更新最后发现日期；`仅索引残留` / `详情不可访问` / `已关闭` 只记日志，不刷新。
- 手工路径必须带 `--confirm-visible` 和 `--reason`。

## 十一、工具语义
- `audit` 只读。
- `add` / `refresh` 即时写入。
- `purge` / `sort` / `repair` / `set` / `recompute` 默认预览，需 `--apply` 才落盘。
- `backup` 为手动备份。
- `repair`：修公式开头、ID 含 BOM、非 JD 说明行。
- `set`：按 ID 补写空值单元格。
- `recompute`：按存量输入列重算分值。
- `sort`：按综合优先级分降序重排。
