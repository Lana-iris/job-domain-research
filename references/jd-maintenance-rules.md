# 岗位数据维护规则（默认规格 · 技能默认）

> 本文件是**通用默认规格**：采集方式 / 匹配逻辑 / 权重公式 / 入库上限与检索下限 / 失效清理 / 文件策略与迭代日志 / 与日报集成 / 合规 / 可达性 / 检索平台 / 公司梯队 / 重新发布。
> **岗位域绑定**的内容只有**检索位矩阵**，写在项目的 `research-state.md`。
> 字段定义见 `references/jd-library-fields.md`（真源）；Excel 保持纯数据。

## 一、采集方式
- 使用公开索引检索（WebSearch 类，非爬取）；**不登录、不突破登录墙**。
- 覆盖缺口 = 未被搜索引擎收录的登录墙岗位，属正常缺失。
- **平台覆盖台账**：每轮按 `templates/platform-coverage.xlsx` 记录 `平台 / 查询词 / 城市 / 检索日期 / 结果数 / 入库数 / 访问限制 / 证据链接`。
- 维护前检查计划平台的每个是否都有状态：**已检索 / 有结果 / 无可核验结果 / 受限 / 未检索**。
- 登录墙平台（如脉脉、Glassdoor、BOSS 直聘）标 **「需用户手动补充」**，**不得伪装为已扫描**。

## 二、匹配逻辑
- 检索位矩阵（见 `research-state.md`）**每词必检**；**每日每词 ≥1 条 query**。
- 关键词子串命中 → 进候选池；去重键＝**公司 + 职位 + 城市**。
- “高信号”露出标签由 **综合优先级分 + 契合度 + 可达性** 共同决定。
- 对高信号岗位提炼：**JD → 能力 → 作品集**（真实市场正在付费的能力证据）。
- **strict 必填四列**（入库前必须写满）：`岗位/职能专有能力要求`、`Market Signal`、`Portfolio Relevance`、`Portfolio Benchmark`；`Immediate Opportunity` ＝ `当前可达性(1-5)`，另作必填。任一为空 → `jd_tool.py add --strict` **拒收**。

## 三、权重公式（默认，可覆盖）
综合优先级分 = 100 × (0.30R + 0.28C + 0.22F + 0.10Ci + 0.10A)

| 维度 | 符号 | 权重 | 取值 |
|---|---|---|---|
| 时效 | R | 0.30 | ≤7 天=1.0；8–30 天=0.75；31–90 天=0.5；>90 天=0.3；**未知=0.4** |
| 公司 | C | 0.28 | C = 0.6×行业分 + 0.4×梯队分（见 §十一） |
| 契合 | F | 0.22 | 契合度(1–5) / 5 |
| 城市 | Ci | 0.10 | 深/广/杭=1.0；北/上/港=0.9；远程=0.9；其他=0.5 |
| 可达性 | A | 0.10 | 当前可达性(1–5) / 5 |

- **发布日期未知 → R=0.4**（不再按 1.0）；存量按需 `recompute`。
- 综合优先级分仅用于**内部**高信号露出与排序，**不作为对外精确排名**。
- 分析时**分别观察三视角**（定性、不参与打分）：Market Signal / Immediate Opportunity（≈当前可达性）/ Portfolio Benchmark；库排序仍按综合优先级分。
- 城市/行业/梯队取值属默认，可按岗位域覆盖。
- **覆盖方式**：权重 / 城市 / 失效阈值 / Sheet 名等默认，可通过 `jd_tool.py --config <config.json>` 覆盖；岗位域层面的覆盖项也可写在 `research-state.md`。

## 四、入库上限与检索下限（默认）
- **持续维护**：所有通过基本相关性与证据核验的岗位都可进累积库；每日「高信号」精选 **≤10**。
- **首轮基线扫描**：不套用每日精选上限；记录 **搜索覆盖 / 候选数 / 去重数 / 核验数 / 状态不明数**。
- **覆盖不足时**：报告检索平台与查询范围；**不为凑数降低岗位质量**；**不把「没有找到」写成「没有机会」**。
- **平台检索下限**：计划平台**每平台每日 ≥ 1 次检索**；0 结果也须在平台覆盖台账记录。

## 五、失效清理
- **自动清理（`purge`）**：`最后发现日期` 距今 >14 天未再发现 → 移入「JD历史·已失效」。
- **人工/审计确认**：`截止日期已过`、`来源显示已关闭·招满` 两类由扫描时人工确认或 `audit` 提示，**不自动清理**（截止日期多为估算，不可直接采信）。
- 每次扫描刷新“最后发现日期”。

## 六、文件策略与迭代日志
- 单本累积；按**去重ID**更新（去重键＝公司 + 职位 + 城市；同岗多平台合并一行，保留最优来源并注明全平台）。
- **迭代日志**：由 `jd_tool.py` 在每次写操作（`add / refresh / purge / sort / repair / set / recompute`）后**自动追加**：`日期 / 变更项 / 旧值 / 新值 / 原因`。技能只做校验：**日志新增行数 == 本轮写操作数**。

## 七、与日报集成
- 岗位库随每日信号日报更新；日报中发现的招聘信号同步录入并标记 **【来自日报】**。
- 日报末尾「今日JD扫描报告」记录：活跃 **a → b** / 新增·刷新·失效 / 三视角提炼 / 0 条三态归因（检索失败 / 有候选全被去重 / 无候选）。
- 周度趋势视图由 O4 承接。

## 八、合规
- 仅聚合公开信息；不爬登录墙、不存任何个人数据。

## 九、可达性
- 可达性 ≠ 契合度：可达性反映“以当前资历能否投进”，随产出物推进应逐月上升。

## 十、检索平台（默认示例）
- 覆盖：LinkedIn 领英 / 猎聘 Liepin / Indeed / 智联招聘 / 前程无忧 51job / 拉勾 / 各公司官网 careers 页。
- 未覆盖（建议手动补充）：脉脉（登录墙）、Glassdoor（登录墙）、BOSS 直聘（索引滞后，仅用户主动粘贴时以【用户补充】入册）。
- 发现新平台及时补充。

## 十一、公司梯队分（默认示例）
- 行业分：互联网/科技/AI/智造/金融科技=1.0；咨询/教育/医疗科技=0.8；传统=0.5。
- 梯队分：大厂=1.0；外企=0.9；中厂=0.8；创业小厂=0.6；未知=0.7。
- 大厂名单（梯队分=1.0 候选，默认示例，按岗位域维护）：
  - 官网可访问：美团 / 腾讯 / 字节跳动 / 阿里巴巴·淘天 / 蚂蚁集团 / 华为 / 百度 / 拼多多 / 京东 / 大疆
  - 未知待验证：快手 / 小米 / 网易 / 小红书 / 科大讯飞 / 滴滴 / 哔哩哔哩

## 十二、重新发布口径
1. 三键（公司 + 职位 + 城市）命中**失效表** 且 **来源显示在招** → `--allow-repost` 重新入册，**备注标原 ID**。
2. 同公司同职能但**不同批次/层级**（校招 vs 社招）→ 视为**不同岗**入册。
3. 同公司同岗同城**多平台** → **合并**。

## 数据字段
- 字段定义见 `references/jd-library-fields.md`（列名 / 含义 / 取值域 / 必填 / 示例）。
- 发布日期：`YYYY-MM-DD`；仅月/年写 `2026-10（日未披露）`；拿不到写 `未知`；**禁止裸写年份**。
